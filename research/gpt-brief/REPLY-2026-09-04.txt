idea-06 — slice-watermark-v2-evidence

layer: L7 · path: both · already_in_ova: partial · effort: L
depends_on_owner: 创建并备份一个本地 attribution root secret；选择每次 upload/build 的 profile。
stop_line_risk: 低。该 secret 永不进入 avatar、永不恢复几何，不是第四把运行时解锁钥。

why_cheap_for_ripper_today: 当前更准确的名称是“seeded vertex perturbation”。默认 seed 公开、固定幅度、按 vertex index 选符号；ova-fp-v1 又不绑定实际 mesh/build，无法支撑抗碰撞、抗伪造的归因链。

what_changes_after:

把 names.seed 与 attribution secret 完全拆开；改名 seed 可以公开且可复现，水印 secret 必须本地生成。
每个 avatar/build 生成唯一 markId，由本地 secret、avatar stable ID、build nonce 和最终 carrier mesh digest 分域派生。
carrier 选择不只依赖原始 vertex index，而依据可重新 canonicalize 的空间/局部几何特征；以免简单 vertex reorder 立即抹掉定位。
采用 spread-spectrum / error-correcting repetition，将短 payload 与认证 tag 分散到大量 carrier。
幅度按 mesh bounds、局部边长和实测量化 margin 自适应，而不是所有 mesh 固定 1e-5。
默认避开 face、eyelid、viseme 高活动区、边界 seam、尖锐轮廓和过低顶点数 mesh。
输出 ova-evidence-v2.json，至少包含：markId、handle hash、build ID、package version、git commit、settings digest、pre/post canonical mesh digests、scheme version、carrier count、amplitude policy、verification result 与签名。
ova-fp-v2 应是 canonical evidence manifest 的摘要，而不是 seed 加三个字段。
本地 verifier 只接收 Owner 已持有的 suspect mesh，输出 decode confidence、有效 carrier 数和 evidence 匹配项。
每次私有 upload/profile 使用独立 markId；配合 Private avatar + 私人实例，能把泄漏范围缩到具体 build，而不是幻想阻断 Path B。

媒介优先级应是：

**第一选择：**最终 geometry 上的自适应 basis watermark；
**第二选择：**只有确认 UV channel 未被 TTT、Shader 或 gimmick 使用时，才把 UV mark 当辅助通道；
**hidden quad：**最多做第二证据或肉眼 ownership 标记，容易被找到和删除，不能当核心；
**topology hash：**只是一条登记指纹，不是嵌入式水印。

why_not: 任意重拓扑、强平滑、大幅 decimation 都可能杀死几何水印；Path B 捕获的是动画后/world-space 几何时，检测成功率也不能先承诺。只有本地签名还不能提供独立第三方时间证明。

test_failure: 未标记 control 出现高置信度、两个 build 重复 markId、修改 evidence 后仍验证通过、正常观察可见形变、vertex reorder 后完全无法定位，或 root secret 丢失后没有恢复方案，即失败。

不再为了“数字一致”在 ova-web 中重写一个假的 NDMF virtual controller。

why_not: 报告不增加保护，但它决定产品是否诚实，并为每个 named slice 提供可证伪结果。

test_failure: UI 在没有实际 build report 时仍显示“最终结果”、report 与 pass 日志不一致、source 变化后不标 stale，即失败。

idea-12 — repair-vpm-artifact-parity

layer: process · path: neither · already_in_ova: partial · effort: S
depends_on_owner: Owner 明确说 repair。
stop_line_risk: 低；不得顺手设计新 VPM 商店或用 PAT 托管私有下载。

why_cheap_for_ripper_today: 实际用户若装到落后的 zip，工作树中所有 FT、viseme、decoy、UI 和修复都等于不存在。

what_changes_after:

对外定性：这是 shipping product bug；
内部根因：缺少 release artifact discipline；
每个修改 Packages/dev.ova.protection/ 或 wwwroot 且准备交付的 slice，其 Definition of Done 必须包括：
compile-check.ps1；
pack-vpm.ps1；
解压 zip 后逐文件 content manifest 对比；
package.json、listing、source commit/version 一致；
host 与 shipping wwwroot hash 一致；
dirty shipping files 或 hash mismatch 时拒绝标 release；
self-hash 只能证明“zip 没变”，不能证明“zip 等于工作树”。

why_not: 这是独立 repair mission；不应与 watermark 或 fixture feature 同窗并行，以免重新制造一个难审计的混合变更。

test_failure: zip 缺任一 required file、版本不一致、manifest 只验证旧 zip 自己、或工作树变化后检查仍绿，即失败。

idea-13 — reject-no-key-vertex-lock

layer: L4 · path: A · already_in_ova: no · effort: S
depends_on_owner: 无。
stop_line_risk: 高；若把弱技巧包装成“加密”就撞产品停线。

why_cheap_for_ripper_today: 当前 basis 正常，针对性提取可直接得到几何；所以“有没有零 bit、原 lilToon 的乱序方案”表面上很诱人。

what_changes_after: 先把理论说准确：

若磁盘 basis 真被打乱，而观看者又能看见正确几何，逆变换必然存在于 Shader、Animator/blendshape、骨骼/skin、参数或客户端代码之一；
在不换 Shader、无 Animator/bone 逆变换、无参数、无客户端代码的条件下，正确渲染不可能发生；
确实存在一个弱反例：把逆变换塞进 always-on corrective blendshape 或骨骼结构，零 synced bit、无需换 Shader；
但它的完整逆变换与规则就在同一 bundle 内，只能阻挡“只看 basis 的朴素工具”，针对性工具可直接求值；关闭 custom animations 时还可能变成刺猬；
因而最多诚实标为 L1.5 self-contained puzzle，不能标为 L4 lock，也不值得成为下一刀。

Kanna 当前官方方案之所以更强，正是因为它使用自定义 Shader 与运行时 key；默认占用 key bits，当前支持列表也没有 lilToon。

why_not: 弱反例带来的兼容、安全显示和维护成本，很可能高于它对定向 Path A 工具增加的劳动；更挡不住 Path B。

test_failure: 任何“反例”必须同时展示：磁盘 basis 错乱、原 lilToon、零运行时逆变换/参数、远端正确显示、且定向恢复不只是应用同 bundle 内的显式 correction。做不到就不是强反例。

idea-14 — docs-three-keys-and-no-fantasy

layer: docs · path: neither · already_in_ova: partial · effort: S
depends_on_owner: 无。
stop_line_risk: 若不做则高，容易重新漂向 SaoMoLa 对抗或运行时锁。

why_cheap_for_ripper_today: 错误口号会让实现代理把大量时间花在 OVA 永远够不到的层。

what_changes_after: 在 docs 与 ova-web 固化五条负面契约：

“有 OVA 源码也拿不到 avatar key”是偷换概念：平台 cache AES 和 UnityPlayer key 本来就不在 OVA 源码里；这不等于 OVA 保护了它们。
“切模时 HTTP 验证再给网格”不是 avatar 能力。VRChat 当前只允许白名单 avatar components；任意 custom scripts 不工作并可能阻止上传。
修改 GameAssembly、进程内 mesh 或 EAC 属于客户端/平台安全，不属于 VPM/NDMF。
没有 _BitKey0..31、DexProtect、_IsLocked 只代表“未被这张 detector table 分类”，不代表没有或具有保护。
Path B 永远显示为 open residual；任何 feature 文案都不得覆盖这一状态。

why_not: 它不是 feature，但能阻止产品使命漂移，并让实现代理知道哪些提案必须立即停止。

test_failure: 任一 UI、README 或营销文字出现“100%”“隐藏平台 key”“观看者联网后才给 mesh”“关闭 Path B”或“未命中检测表=安全”，即失败。
